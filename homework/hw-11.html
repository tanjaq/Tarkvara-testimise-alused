Homework 11 — SQL Verification — Shop Database

Individual or pairLesson 11Submit: Queries + defect list

Objective

Prove things about data instead of trusting the screen — and see which defects a missing constraint lets through.

Task

  1. Open sqliteonline.com (or any SQLite client). Paste shop-database.sql and run it.
  2. The nine requirements the application is supposed to guarantee are listed in comments at the top of the file.
  3. Write one query per requirement that checks whether the data actually honours it. A good check returns zero rows when everything is fine, and the offending rows when it is not.
  4. Run the join comparison suggested at the bottom of the file: JOIN versus LEFT JOIN on orders and customers. Explain the difference in the row count.
  5. Find the defects. There are at least six. For each one record: the query that found it, the rows returned, which requirement it breaks, and the severity you would assign.
  6. For each defect, name the database constraint that would have prevented it — NOT NULL, UNIQUE, FOREIGN KEY or CHECK.
  7. Finally: one of the requirements is about money. Look at how prices and totals are stored and say what you would change, and why.

Deliverable

Your queries, the defects found with evidence, the constraint that would have prevented each, and your note on the money storage.

Assessment criteria

CriterionWhat we look for
Query per requirementEach requirement has a check that returns rows only when it is violated
Defects foundAt least six, correctly mapped to the requirement they break
ConstraintsThe right constraint is named for each defect
Join understandingYou can explain the row-count difference between JOIN and LEFT JOIN
SeverityAssigned and justified per defect
