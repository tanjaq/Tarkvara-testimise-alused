Homework 9 — Test Plan and Test Cases for Your Project

Group projectLesson 10Submit: Teams

Objective

Close the loop: the requirements you wrote in Homework 3, now verified by a plan that says how you will test them and by cases that actually do it.

Task

  1. Part 1 — the test plan. Write it into your SRS document, section 7.1 Test Plan. Keep it to one page. It must contain:
  2. • Scope — which parts of the system the plan covers, and at which test level
    • Features to be tested — listed explicitly and traceable to the functional requirements in section 3
    • Features not to be tested — and why
    • Test approach — which techniques from Lessons 7 and 8 you will use, and what you will test manually
    • Entry and exit criteria — when testing can start, and when it is finished
    • Test environment and test data — which environment, which accounts, which data
    • Risks and mitigations — what could stop testing, and what you will do
    • Deliverables and schedule
  3. Write the exit criteria so that someone outside your team could look at your project and answer yes or no. "Testing is done when it works" is not an exit criterion.
  4. Writing the plan usually finds requirement defects — a behaviour nobody has decided yet. Note those; they count in your favour.
  5. Part 2 — the test cases. Add them to your SRS document, section 7.2 Test Cases.
  6. The test cases must cover all of your functional requirements — check them off one by one against section 3.
  7. Each test case needs: ID and title, description and the requirement it covers, preconditions, numbered steps, test data, expected results, and a status column.
  8. Include negative and edge cases, not only the happy path. Use equivalence partitioning and boundary value analysis to decide which values to test.
  9. Keep each case focused on one scenario, and make sure no case depends on the output of another.

Deliverable

Your SRS document with section 7.1 Test Plan and section 7.2 Test Cases completed.

Assessment criteria

CriterionWhat we look for
Plan is completeAll eight parts of the test plan are filled in, including what will not be tested
Exit criteria are checkableSomeone else could decide from them whether testing is finished
Approach matches the productThe chosen techniques fit what your system actually does
TraceabilityEvery functional requirement has at least one test case, and every case names its requirement
ExecutableAnother team could run your cases without asking questions
Measurable expected resultsNo "works correctly"
Negative coverageInvalid input and edge cases are included
