Using AI Responsibly in Testing

Where AI helps · Where it fails silently · Ground rules

→ next slide  |  ESC overview

Why This Lesson Exists

AI Is Already in Your Toolchain

Copilot, ChatGPT, Cursor, Claude — these are part of the developer toolkit now. Nobody is going to ask you whether you used one. They are going to ask whether the result is correct.

Everything in this course — requirements, techniques, coverage, defect reports — is what turns "the AI produced something" into "I know this is right".
Topic 1

Where AI Genuinely Helps

Good uses · Generate boilerplate and scaffolding
· Draft a first set of test cases from a requirement
· Suggest edge cases you might have missed
· Explain code you did not write
· Speed up a first-pass refactoring
· Turn a vague requirement into questions to ask the analyst
Where it fails silently · It does not know your requirements
· It does not understand your system's context
· Generated tests are often shallow — happy path only
· Code looks clean while the logic is subtly wrong
· It produces wrong answers with complete confidence

AI-generated code compiles. It might even pass basic tests. That does not make it correct.

Topic 2

Test First, Then Let AI Write the Code

You write the test
you define what correct means — AI has no say here
→
AI writes the code
let it generate — then read what it produced
→
Tests judge the result
does it pass? are the edge cases covered?

This ordering is the whole trick. If the tests come first and they came from the requirements, then the AI cannot quietly redefine what "working" means.

Topic 3

Ground Rules

Do

  • Use AI for boilerplate and first drafts
  • Use AI to suggest test cases — then review them
  • Read everything AI writes before you commit it
  • Run your full test suite against AI output
  • Ask AI to explain its reasoning — gaps appear fast

Don't

  • Submit AI output you do not understand
  • Treat AI-generated tests as complete coverage
  • Skip code review because "AI wrote it"
  • Accept a passing test as proof of correctness
  • Let AI define your requirements for you

AI is a junior developer who works fast and never complains — and always needs review.

Topic 4

Try It — and Then Check It

  • Take one functional requirement from your SRS. Ask an AI tool to write test cases for it.
  • Now apply Lesson 7: does it cover the equivalence partitions? The boundaries? Any negative cases?
  • Count what is missing. That gap is the value you add.
Students who can say exactly what an AI missed are the ones who get hired. Anyone can paste a prompt.
